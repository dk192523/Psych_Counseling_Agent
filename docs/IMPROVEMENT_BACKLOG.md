## P1：检索质量（有基线后再变更）

当前来源案例命中 Recall@4=4%，MRR@4=0.02；5 个无关问题均有结果。种子标签只标记来源案例，不穷尽所有相关案例，需要人工复核。不要把这组数解释为真实用户总体准确率。

1. 独立标注 50–100 条真实表达，标出所有合理相关案例、无结果与危机转介场景；保留独立测试集。
2. 对比中文/多语种 embedding、词法+向量混合检索、按 tokenizer 窗口切块。记录同一评测集的召回、MRR、拒答/无结果和延迟。
3. 验证阈值与无结果分支，再切生产模型；模型改变涉及向量重建和维度兼容，不能只改字符串。
4. 当前基线采用精确余弦，未覆盖 pgvector HNSW、深度规划/重排和最终作答；这些层需各自验证。

## P1：生产隐私与真实链路验收

- 正文、摘要仍为数据库明文；落实卷/磁盘及备份加密、保留期限、恢复演练。列级加密需要独立迁移、密钥管理和检索设计，不能未经迁移测试直接覆盖现有数据。
- 正式域名 TLS、Cookie、Worker/LLM 实际调用、危机路径需上线前 E2E；本轮未调用付费模型。
- 检查知识库来源授权、隐私边界、案例与时间戳准确性；安全规则不等于临床认证。

## P2：性能、观测与前端结构

- searchRecallCandidates 的查询有 conversation_id 限制与索引，不应直接称为全库扫描。ILIKE 用于排序；添加 trigram 索引不必然帮助，需要大规模数据 EXPLAIN 后再改写查询。
- token 指标只覆盖接入该 Advisor 的 ChatClient 回复，Worker、工具和失败/取消流 usage 仍可能缺失；异步 MDC 贯通、Prometheus 告警和账单对账未完成。
- PsychMaster 已抽离 SSE/CSRF，但页面仍较大；可继续拆会话、密码弹窗和记忆刷新 composable，保持现有交互测试。
- 墓碑表保留、历史保留与账号全量数据导出仍需产品规则；七天重放缓存不会替代主历史保留策略。

## 单副本限制

会话注册表、限流、模型窗口和启动时 RUNNING 恢复均依赖单实例。要支持多副本，需共享会话/限流、生成租约与 fencing、跨实例吊销、整合协调。sticky session 单独不能解决这些问题。当前禁止重叠滚动发布。
