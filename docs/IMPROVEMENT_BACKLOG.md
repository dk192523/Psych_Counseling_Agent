## P1：生产隐私与真实链路验收

- 正文、摘要仍为数据库明文；落实卷/磁盘及备份加密、保留期限、恢复演练。列级加密需要独立迁移、密钥管理和检索设计，不能未经迁移测试直接覆盖现有数据。
- 产品与法律保留期限尚待明确，不能从 1000 条记忆工作集或七天轮次缓存推导。启用 `DATA_RETENTION_APPLY=true` 前须在隔离数据库验证 dry-run、并发 begin/delete、墓碑防复活与失败重入，并检查实际候选范围；业务删除不等于备份/WAL/快照/磁盘擦除，还需恢复后的删除重放策略。
- 正式域名 TLS、Cookie、Worker/LLM 实际调用、危机路径需上线前 E2E；本轮未调用付费模型。
- 检查知识库来源授权、隐私边界、案例与时间戳准确性；安全规则不等于临床认证。

## P2：性能、观测与前端结构

- searchRecallCandidates 的查询有 conversation_id 限制与索引，不应直接称为全库扫描。ILIKE 用于排序；添加 trigram 索引不必然帮助，需要大规模数据 EXPLAIN 后再改写查询。
- token 指标只覆盖接入该 Advisor 的 ChatClient 回复，Worker、工具和失败/取消流 usage 仍可能缺失；异步 MDC 贯通、Prometheus 告警和账单对账未完成。
- PsychMaster 已抽离 SSE/CSRF，但页面仍较大；可继续拆会话、密码弹窗和记忆刷新 composable，保持现有交互测试。
- 墓碑当前永久保留以阻止旧会话复活；其容量管理、账号全量数据导出仍需产品规则。整会话保留机制已具备，但产品期限未配置、默认不执行删除；七天重放缓存不会替代主历史保留策略。

## 单副本限制

会话注册表、限流、模型窗口和启动时 RUNNING 恢复均依赖单实例。要支持多副本，需共享会话/限流、生成租约与 fencing、跨实例吊销、整合协调。sticky session 单独不能解决这些问题。当前禁止重叠滚动发布。

## 单副本启动门禁（2026-09-20）

Java 后端仅支持 `APP_DEPLOYMENT_MODE=single`、`APP_REPLICA_COUNT=1`（默认值）；其他模式、空值、非整数、零、负数及任何不等于 1 的副本数都会拒绝启动。`DkAiAgentApplication.main` 首先检查环境变量，再于 Spring 环境准备事件中复核 YAML/profile/命令行最终值；拒绝发生在 Bean 初始化前，避免启动时全库 RUNNING 恢复及向量库灌注先执行。

`APP_INSTANCE_ID` 可选，空白或未配置时每次进程启动生成新 UUID；显式值允许 1..128 位 ASCII 字母、数字、点、下划线、冒号和连字符。解析后的值供启动日志和 `app.deployment.instance-id` 观测使用，不进入咨询正文，也不是分布式锁或 fencing token。不要在所有实例中复用固定默认 ID。

部署与升级必须先停止旧 Java 后端、确认进程完全退出，再启动新后端，接受短暂中断；禁止重叠滚动发布、双实例蓝绿切流和 `--scale backend=2`。Compose 变量只是部署声明，不能测量真实副本数：两个连接同一数据库的实例即使都声明 single/1，门禁也无法自动发现。

真正多副本仍需共享 Session/跨实例吊销、全局限流、turn lease/fencing、记忆整合协调和按所有权恢复 RUNNING 轮次；sticky session 与 instance ID 均不能替代这些能力。本次门禁和纯单元测试已添加，但本次未运行测试或真实数据库验证。
