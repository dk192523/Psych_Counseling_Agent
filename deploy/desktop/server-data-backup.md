# 本地服务端数据备份与隔离验证

这项功能用于已安装的 `PsychCounselorServer`：在同一台 Windows 电脑、创建备份的同一 Windows 用户下创建加密冷备，并把备份恢复到独立目录进行只读验证。入口位于服务端托盘的“打开服务管理”窗口。客户端不持有数据库或密钥，也不提供备份入口。

旧 Docker/服务版 PostgreSQL 到桌面 Server 加密 H2 的自动迁移尚未实现：安装新的 Server 不会自动导入账号、会话或消息，也不会删除原数据库。当前实现还不提供正式数据覆盖恢复、备份合并、跨电脑/跨 Windows 用户迁移或 PostgreSQL 远程服务端备份。隔离验证成功表示备份能够认证、清单校验通过、原凭据可解开 H2 数据库且当前版本所需表可查询，不代表已完成正式服务恢复或验证了咨询质量。

## 创建备份

1. 从 Server 托盘打开服务管理，先等服务显示正在运行。
2. 选择“创建加密备份…”，在系统保存对话框中选择一个新的 `.psychbackup` 文件名。目标必须位于服务数据目录以外、支持 Windows 用户 ACL 的本地磁盘；网络盘、符号链接、目录联接和不支持 ACL 的文件系统会被拒绝。已有同名文件不会覆盖，即使保存对话框曾提示替换，也会拒绝创建。
3. 管理器撤回本机端点，在自己的生命周期线程停止 Spring，并在整个备份和重启过程中继续持有 `desktop.lock`。没有确认关闭或 H2 数据库文件锁仍被占用时，不复制数据库。
4. 备份先写入同目录的随机 `.partial` 文件。文件从创建时就限制为当前 Windows 用户访问；ZIP 和加密流完成后刷新到磁盘，重新读取并验证认证、长度及 SHA-256，最后使用禁止覆盖的同目录原子重命名创建正式文件。
5. 完成或出现异常后，管理器尽力重新启动服务；只有 readiness 通过后才重新发布端点。窗口会区分“备份已经保存”和“备份未完成”，服务重启失败时提供重试入口。

冷备会暂停 API，当前聊天和 SSE 连接会中断。服务重新就绪后，在客户端重试连接；随机端口可能变化，应由客户端重新发现端点。不要在备份过程中强制结束 Server 进程；正常“退出服务”会取消未完成操作并排队清理。

源文件固定为：

```text
%LOCALAPPDATA%\PsychCounselor\
  data\counseling.mv.db       # H2 CIPHER=AES 数据库
  secrets.dpapi               # 当前用户的数据库文件密钥、API Key 等加密凭据
  desktop.lock                # 运行锁，不进入备份
```

源 `data` 下的目录、链接或特殊文件会导致备份被拒绝；额外普通文件不会装入备份。备份 ZIP 只有 `counseling.mv.db`、`secrets.dpapi` 和 UTF-8 `manifest.properties` 三个条目。端点、连接偏好、启动项、日志、Worker、安装程序和原始资料都不进入备份。

## 验证备份与隔离恢复

1. 选择“验证备份（隔离恢复）…”，使用系统打开对话框选择 `.psychbackup`。服务已经运行时，验证不需要停服；启动失败的管理窗口也提供此入口。
2. 先解开 DPAPI 包装的外层密钥，逐段认证整个容器，并校验明确的结束标记与文件 EOF。密钥解密失败、内容篡改、截断或末尾追加内容都会失败，不会进入数据库验证。
3. 在当前用户目录下创建全新的 UUID 目录，不接受用户指定的恢复位置，不复用已存在的演练目录。认证后的 ZIP 临时文件以及最终副本都只写入本次 `data` 目录：

```text
%LOCALAPPDATA%\PsychCounselor\restore-drills\<UUID>\data\
  counseling.mv.db
  secrets.dpapi
  manifest.properties
```

4. ZIP 必须恰好包含三个固定条目；路径穿越、绝对路径、子目录、重复条目、未知条目、缺失条目、无效清单或超限数据会被拒绝。每份副本都通过清单长度和 SHA-256 校验。
5. 仅加载副本中的既有 `secrets.dpapi`，绝不生成替代密钥。通过 H2 `CIPHER=AES;IFEXISTS=TRUE;ACCESS_MODE_DATA=r` 只读打开副本，查询账号、会话、消息、记忆、墓碑、聊天轮次和本地向量表；不启动 Spring，不执行初始化、迁移、模型调用或生产目录写入。
6. 验证成功后保留三个副本，窗口显示备份时间和隔离目录。隔离副本没有接入服务；请按需要妥善保留或自行删除。失败时仅清理本次创建的固定文件和空目录，不递归删除任意路径；权限或外部改动妨碍清理时，可能留下受 ACL 保护的隔离文件，检查 `restore-drills` 即可。创建备份时的内部校验不保留演练副本。

## 加密格式与边界

外层格式版本为 `1`：随机 256 位 AES 密钥，通过当前用户范围 DPAPI 包装，未使用 `CRYPTPROTECT_LOCAL_MACHINE`。另以本机 Windows `MachineGuid` 的带用途标识哈希作为 DPAPI 附加熵，限制域账号凭据漫游时的跨设备使用；标识不会写入清单、日志或 UI。Windows 重装、机器标识改变或当前用户 DPAPI 主密钥丢失都可能导致旧备份无法解密。

ZIP 流按 64 KiB 分段使用 AES-GCM，128 位认证标签；每份备份使用随机密钥和随机 nonce 前缀，每段使用单调编号。完整容器头部、分段编号和明文长度均参与 AAD，最后另有经过认证的空结束段，不能删除、拼接或重新排序有效分段。分段解密让内存使用保持有界，避免解密大文件时一次缓冲整份 ZIP。

数据库和凭据在 ZIP 内仍保留原有 H2/DPAPI 加密，清单只记录格式版本、备份时间、文件长度和哈希。备份、临时文件和隔离目录创建时使用当前用户的私有 ACL，文件不显示数据库密码、API Key 或备份密钥。

当前限制：H2 数据库不超过 8 GiB，凭据不超过 128 KiB，清单不超过 16 KiB；容器及 ZIP 另有整体限制。备份创建与校验需要读取数据库数次，耗时随文件大小增长；隔离验证期间同时存在 ZIP 临时文件和数据库副本，请预留约两倍数据库大小的额外可用空间。此格式仍是本地恢复保障，不是 Windows 用户/磁盘彻底丢失后的灾难恢复方案。

本次仅完成编码与文档，未运行新增单测、构建、桌面交互或恢复演练，也未执行自审。发布前仍需在普通 Windows 用户环境验证 DPAPI、ACL、数据库关闭、故障后的服务恢复及全流程界面行为。
